# Miss Minutes — $10,000 delivery plan

**Status:** proposed delivery contract and scope allocation

**Date:** 18 November 2026

## 1. Commercial standard

The 10,000 USD figure is treated as the engineering scope and quality benchmark requested for this product. This document does not assert that money has been transferred, spent or received. The allocation is a work-package budget, not a promise that Android can reproduce fictional hardware or bypass platform rules.

The commission is for a real Android personal assistant named **Miss Minutes**, inspired by the useful breadth of J.A.R.V.I.S. It is not a plain chat UI, a scripted demo or a collection of buttons with no runtime behavior.

## 2. Baseline decision

**Continue the existing repository; do not rewrite it from scratch.**

The current Kotlin app already has an Assistant-role foundation, speech/TTS, AI provider abstraction, bounded tool loop, task graph runner, device actions, Accessibility automation, SMS triage, encrypted conversations and Compose screens. Those are expensive foundations to throw away. The correct investment is to stabilize them, establish clean contracts, refactor the monolithic UI and build missing features behind tests.

The current repository has one app Gradle module. Create stable package/API boundaries first and extract modules incrementally. Do not perform a large architecture migration and a large user-facing feature migration in the same uncontrolled change.

## 4. Delivery phases and exit gates

### P0 — Stabilize and establish truth

Scope:
- Audit exact main, branches, open PR bases and build pipeline.
- Repair failing tests/lint/build defects; keep security checks enabled.
- Make architecture and capability documentation match code.
- Define capability status and risk/approval rules.
- Add baseline screenshots/benchmarks and issue-linked acceptance criteria.

Exit gate:
- Exact-head JVM tests, lint, debug/release builds and instrumentation are green.
- No known critical secret or permission regression.
- Every baseline capability is tagged as working, partial or absent.

### P1 — Separate product surfaces from the monolith

Scope:
- Extract Compose screens and view models into feature-owned files/packages.
- Establish design tokens, typography, spacing, status colors, component semantics and navigation.
- Introduce a typed assistant event renderer for text, cards, plans, tool states, approvals, tables and charts.
- Create a single CapabilityCatalog that drives dashboard, settings and model tool schemas.

Exit gate:
- Existing chat, history, settings, backups and voice flows retain behavior.
- UI tests cover navigation, TalkBack semantics, localization and loading/error/empty states.
- No feature silently advertises an unimplemented tool.

### P2 — Complete the system Assistant experience

Scope:
- Implement a genuine VoiceInteractionSession flow connected to the shared conversation runtime.
- Handle role onboarding, role loss, service lifecycle, audio focus, interruption and Stop.
- Use hardware/system hotword only when available; preserve explicit SpeechRecognizer fallback.
- Expose capability and battery state truthfully.

Exit gate:
- Assistant invocation and conversation pass instrumentation on supported Android versions.
- Role denial/loss and microphone permission revocation fail safely.
- Physical-device wake latency, false wakes and battery use are measured.
- Unsupported devices receive a clear manual/voice fallback.

### P3 — Production conversation and agent runtime

Scope:
- Streaming provider contract and cancellable turn state machine.
- Context budget and language routing for Tajik, Russian and English.
- Bounded structured planner and tool dispatcher backed by CapabilityCatalog.
- Per-action approvals, idempotency, rate limits, deadlines, verification and recovery.
- Optional on-device and cloud provider routing with explicit privacy modes.

Exit gate:
- Adversarial model output cannot bypass policy or invoke unregistered tools.
- No duplicate write after timeout or process death.
- Provider errors/cancellation preserve conversation state and do not claim success.
- Local mode never pretends tools are available when they are not.

### P4 — Useful Android capabilities and communications

Scope:
- Stabilize device, calendar, contact, alarm and app actions.
- Resolve the current hard-coded calendar-ID assumption and validate writable calendars.
- Harden Accessibility target resolution and action verification.
- Add NotificationListenerService with separate user-granted access.
- Expand SMS triage only within role, permission and data-retention limits.
- Add supported contact/call/message hand-off; do not implement covert recording.

Exit gate:
- Permission-denied, role-lost, no-default-calendar, duplicate SMS and malformed event tests pass.
- Raw SMS/OTP content is excluded from analytics and general memory.
- Each action has a clear result and a revocation path.

### P5 — Memory and proactive assistance

Scope:
- Unified local memory model with working, episodic, semantic and operational layers.
- Inspect/edit/delete, retention and source provenance.
- Reminders, recurring routines, calendar briefing and task follow-up.
- Avoid background work that Android cannot reliably schedule.

Exit gate:
- Data migrations, backup exclusions, deletion, key invalidation and process recovery tested.
- User can identify and remove each saved memory.
- Proactive notifications are opt-in, explainable and rate-limited.

### P6 — Multimodal intelligence

Scope:
- User-selected images and documents.
- Explicitly authorized screen sharing/capture and camera sessions.
- Multimodal inference adapter and structured visual results.
- Clear capture indicator, source scope, local/cloud choice and deletion.

Exit gate:
- No hidden capture; denied/revoked consent stops acquisition.
- Secure surfaces and excluded content are respected.
- Large files, low-memory conditions and unsupported providers fail gracefully.

### P7 — Premium assistant experience

Scope:
- Home Command Center with presence, status, briefings, actions and live task.
- Rich conversation: streaming blocks, plan cards, tool cards, approval cards, tables, charts, images and files.
- Searchable categorized capability catalog and connection states.
- Activity/task center, memory management and Trust Center.
- Optional animated 2D/3D Miss Minutes character as a presentation-only layer.
- Fully localized English/Russian/Tajik, adaptive layouts, accessibility and reduced motion.

Exit gate:
- Every visible control is backed by a real feature or explicitly marked as coming soon/unsupported.
- Compose UI tests cover states and interactions, not only screenshots.
- Avatar can be disabled and does not own assistant logic or background audio.

### P8 — Security, performance and release hardening

Scope:
- Permission and role matrix, data-flow review, threat modeling and dependency audit.
- Static analysis, secret scanning, dependency review and SBOM.
- Release signing outside source control; checksums and provenance.
- Lifecycle, doze, reboot, background-start restrictions, thermal and battery tests.
- Physical-device matrix and release/handover documentation.

Exit gate:
- Required GitHub checks are green for exact release commit.
- No open critical/high security defect.
- Physical-device tests and known limitations are documented.
- Debug and release artifacts are reproducible, signed appropriately and accompanied by checksums.

## 5. Product experience specification

The app has six coherent surfaces:

1. **Command Center** — assistant presence; online/offline and role state; voice/listening state; quick actions; current task; concise briefing; recent activity.
2. **Conversation** — streaming dialogue with rich result blocks, task plans, tool progress, inline approvals, attachment context and clear error recovery.
3. **Capability Catalog** — categories for Intelligence, Voice, Phone Control, Communication, Memory, Vision, Productivity and Connected Devices; cards show availability, scopes and enable/test path.
4. **Tasks & Activity** — queued, running, waiting for approval, completed, failed and recovery-required states with an inspectable event timeline.
5. **Memory** — searchable saved context with source, timestamp, edit/delete and retention controls.
6. **Trust Center / Settings** — AI provider and offline model, roles and permissions, connected services, privacy, audio, language, theme, backups and diagnostics.

The interface should be premium through information architecture, clarity, motion discipline and reliability — not decorative neon, fake telemetry or animated elements that slow down actions. The same event schema must render consistently in the chat, dashboard and task center.

## 6. Non-negotiable acceptance tests

- Clean install and upgrade from previous schema.
- Assistant role accepted, denied, revoked and restored.
- Microphone unavailable; recognizer unsupported; audio focus lost; user interrupts TTS.
- Network absent, provider rate-limited, malformed structured response and cancelled request.
- Tool absent from catalog, malformed arguments, consent revoked, OS permission denied and approval expired.
- Process death before and after external side effect; duplicate broadcast; duplicate retry.
- SMS receiver called without role/permission; notifications access disabled; sender excluded.
- No writable calendar, calendar ID not equal to 1, calendar provider unavailable.
- Accessibility target missing, ambiguous or secure; password/OTP/high-risk control blocked.
- Local memory encrypted, deleted, restored and key invalidated; backup excludes secrets.
- Large image/document, capture denied/revoked, low-memory and thermal fallback.
- Tajik, Russian and English strings, speech settings and action explanations.
- TalkBack, large font, landscape, dark/light theme and reduced motion.

## 7. Scope exclusions and dependencies

The Android application itself cannot provide:
- Iron Man armor, flight controls, life-support systems, weapons or Iron Legion robotics.
- Universal access to all phone apps, all sensors or secure Android surfaces.
- Guaranteed hardware hotword support or uninterrupted background execution on every OEM.
- Medical-grade vital signs without a validated paired sensor and suitable regulatory/product design.
- Automatic access to private systems, accounts or devices without the owner's authorization.

External services, hosted model fees, device purchases, licensed 3D assets and third-party API charges are not silently included in this engineering allocation. Each requires a reviewed cost, license, privacy and availability decision. Large model weights should not be bundled in the APK; local inference remains conditional on compatible models and device memory/performance.

## 8. Change-control rule

Each phase is delivered as small reviewable GitHub changes:
- One scoped branch or PR per coherent work package.
- Tests added with the feature, not postponed to the end.
- No bulk merge of stale/stacked PRs without rebase, conflict resolution and exact-head CI.
- Do not weaken tests, suppress lint broadly or create false success telemetry to make CI green.
- Merge only after the required checks pass and acceptance criteria are demonstrated.
- Update this plan when evidence changes; never claim an untested feature is complete.
